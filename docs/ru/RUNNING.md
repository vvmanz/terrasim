# Запуск симуляций

[English version](../en/RUNNING.md)

Три точки входа:
* `scripts/drive.sh` — **песочница**: любой робот проезжает траекторию по карте рельефа, с регулятором или без, с
  одометрией и IMU; по каждому прогону лог, рисунок и метрики (§1–§6);
* `scripts/robotino.sh` — **«звезда» Robotino**: датасеты в формате лабораторных записей Robotino ([DATASETS](DATASETS.md));
* `python3 tools/traverse.py` — **матрица проходимости**: каждый робот × поверхность × уклон (§8).

Все скрипты принимают `--engine harmonic` (Gazebo Harmonic) или `--engine emulate` (офлайн-ядро, без Gazebo); см.
[PHYSICS](PHYSICS.md#4-движки). ROS 2 — [ROS2](ROS2.md).

## 1. Быстрый старт

Больше примеров по шагам (свой робот, поверхность, карта) — [EXAMPLES](EXAMPLES.md).

```bash
cd ~/terrasim
bash scripts/drive.sh --list                                   # роботы, поверхности, траектории, рельефы и узоры, карты
# Robotino на шахматке серая / ковролин, круг R = 1 м, эмулятор (секунды)
bash scripts/drive.sh --engine emulate --robot robotino --floor checkerboard:surfaces=gray+carpet,cell=0.5 --traj circle:R=1
# Husky на кратерах, квадрат со скруглёнными углами, окно Gazebo в реальном времени
bash scripts/drive.sh --engine harmonic --robot husky --relief craters:n=5,R=1.5,depth=0.15,flat0=1.5 --traj square:L=4,rc=0.6 --gui
# youBot: восьмёрка боком (фиксированный курс) и лицом по ходу, без регулятора и с ним (4 прогона)
bash scripts/drive.sh --engine emulate --robot youbot --traj figure8:A=1.2 --heading fixed,tangent --control open,closed
# готовая карта со своим сценарием и роботами
bash scripts/drive.sh --map slope_ladder
# набор примеров: 9 небольших исследований, несколько минут в эмуляторе
bash scripts/drive_examples.sh              # или: bash scripts/drive_examples.sh harmonic
```

Движок по умолчанию у `drive.sh` — `emulate`, у `robotino.sh` и launch-файлов ROS 2 — `harmonic`. `--gui` открывает
окно Gazebo (по умолчанию в реальном времени; `--rtf 5` — в пять раз быстрее); без `--gui` Gazebo работает без окна
так быстро, как может.

## 2. Ключи `scripts/drive.sh`

Значения через запятую (`--robot`, `--control`, `--localization`, `--heading`, `--drive`, `--motor-control`) или через
`|` (`--traj`, `--floor`, `--relief`) запускают по прогону на каждое сочетание — пакет. Значения с `;` или `|` берутся
в кавычки: `--traj "spline:pts=1,0.5;2,0" --relief "craters:n=4;bumps:n=20"`.

| ключ | по умолчанию | смысл |
|---|---|---|
| `--robot` | robotino (с `--map` — роботы карты) | встроенный робот, имя файла робота из `configs/robots/` или путь к файлу робота ([ROBOTS](ROBOTS.md)) |
| `--engine` | emulate | `harmonic` или `emulate` |
| `--map` | – | файл карты: `NAME`, `NAME@scenario`, `"NAME@*"`, путь; список через запятую — пакет ([MAPS](MAPS.md)) |
| `--map-set` | – | поменять значение файла карты: `relief.0.slope_deg=12` |
| `--relief`, `--floor` | flat, uniform | сгенерированный рельеф вместо файла карты ([MAPS](MAPS.md#6-генераторы-в-командной-строке---relief---floor)) |
| `--surface` | gray | покрытие однородного пола; с `--map` заменяет покрытие карты по умолчанию |
| `--surface-file` | – | дополнительные поверхности (JSON, [SURFACES](SURFACES.md#4-своя-поверхность)) |
| `--map-size`, `--res` | по роботу | полуширина генерируемой квадратной карты и шаг её сетки, м |
| `--spawn` | 0,0,0 | x, y, курс (°) точки старта в системе карты (отрицательные: `--spawn=-2,0,0`) |
| `--traj` | по роботу | траектория (§3) |
| `--speed`, `--accel` | по роботу | крейсерская скорость, м/с, и ускорение трапеции, м/с² |
| `--drive` | первый у робота | `holonomic` (омни, меканум) или `diff` |
| `--heading` | tangent | только holonomic: `tangent` (лицом по ходу) или `fixed` (держит начальный курс, едет боком) |
| `--control` | closed | `open` (без регулятора) или `closed` (регулятор пути) (§4) |
| `--localization` | truth | обратная связь регулятора: `truth`, `odom`, `odom_imu` |
| `--motor-control` | speed | `speed` (ПИ-контур скорости) или `voltage` (U = Ce·ω_зад, без контура мотора) |
| `--imu-noise`, `--imu-rate`, `--seed` | default, 100 Гц, 11 | пресет шума IMU (§5), частота IMU, зерно случайных чисел |
| `--ctrl-rate` | 50 Гц | частота регулятора пути и одометрии |
| `--t-start`, `--t-settle` | 1.5 с, 2 с | стоянка до движения (калибровка нуля гироскопа) и после |
| `--set` | – | `имя.параметр=значение`: robot, motor, wheel, caster, controller, imu, contact, trajectory, body (`k`, `c`, `mu`) или поверхность ([ROBOTS](ROBOTS.md#21-на-один-прогон---set)) |
| `--kn-scale`, `--no-contact-scale` | 1, выкл. | мягче колёса (< 1); не масштабировать жёсткость контакта по нагрузке |
| `--body-contact` | on | корпус касается земли (падения, опрокидывания, робот на брюхе на кочке); `off` — проходит сквозь неё ([PHYSICS §2.7](PHYSICS.md#27-контакт-корпуса-с-землёй-падения-и-опрокидывания)) |
| `--on-tip`, `--tip-deg` | stop, 50 | когда корпус наклонился к земле больше чем на `--tip-deg`: `stop` — прогон заканчивается через 0.2 с, `continue` — робот кувыркается, прогон идёт дальше |
| `--body-mu` | 0.6 | трение корпуса о землю |
| `--replay`, `--replay-mode`, `--truth`, `--v0` | – | воспроизвести записанные команды вместо траектории (§6) |
| `--gui`, `--rtf` | выкл., 1 с окном | окно Gazebo; темп относительно реального времени (0 — как можно быстрее) |
| `--gz-sensors` | выкл. | Harmonic: штатные IMU (`/imu`), OdometryPublisher, JointStatePublisher Gazebo |
| `--ros`, `--gz-partition` | выкл. | публиковать прогон в ROS 2 ([ROS2](ROS2.md)) |
| `--jobs` | 1 | прогонов параллельно |
| `--dt`, `--log-rate`, `--full-rate`, `--no-full` | 0.001 с, 50 Гц, 50 Гц | шаг физики, частота `log.csv`, частота `full.csv.gz` / не писать его |
| `--stall`, `--progress` | 120 с, 15 с | остановить прогон, если лог перестал расти; интервал печати хода |
| `--out`, `--no-figures` | `runs_drive/<дата>_<движок>` | папка результатов; без рисунков |

Полный список с текущими значениями: `python3 tools/drive_run.py --help`. Результаты — [OUTPUTS](OUTPUTS.md).

## 3. Траектории

Траектория задаётся в **стартовой системе**: начало там, где стоит робот, +x — куда он смотрит. Поэтому одна
траектория работает при любой точке старта.

| вид | параметры (по умолчанию) | что это |
|---|---|---|
| `line` | `L`=3, `angle`=0 | отрезок; `angle` — направление в стартовой системе (с `--heading fixed` голономный робот едет боком) |
| `circle` | `R`=1, `loops`=1 | окружность против часовой (R < 0 — по часовой), вход по касательной |
| `square` | `L`=2, `rc`=0.3, `loops` | квадрат против часовой, углы скруглены радиусом rc (rc = 0 — острые, только для голономных) |
| `rect` | `Lx`, `Ly`, `rc` | прямоугольник |
| `figure8` | `A`=1.5, `loops` | восьмёрка (лемниската Жерона) полушириной A |
| `spline` | `pts=x1,y1;x2,y2;...` | сплайн Катмулла–Рома через точки (стартовая система, м) |
| `slalom` | `L`=4, `A`=0.4, `n`=2 | слалом вдоль +x |
| `spiral` | `R0`=0.3, `R1`=1.5, `turns`=2 | спираль наружу |

Скорость вдоль траектории — трапеция (разгон `--accel`, крейсер `--speed`, торможение); опорная точка движется по
времени. `python3 tools/trajectories.py "figure8:A=1.2" --plot` рисует траекторию.

## 4. Без регулятора и с регулятором

**`--control open` — без регулятора.** Опорная скорость и кривизна дают скорости колёс через обратную кинематику, они
идут в контуры скорости моторов. Робот едет «вслепую»: проскальзывание и занос копятся в ошибку пути.

**`--control closed` — регулятор пути** (50 Гц): прямая связь по опоре плюс обратная связь.
* голономный режим: P-регулятор по положению (`kp_xy`) и курсу (`k_yaw`);
* diff: закон Канаямы. Продольная, боковая и курсовая ошибки e_x, e_y, e_θ:
  v = v_r·cos e_θ + k_x·e_x, ω = ω_r + v_r·(k_y·e_y + k_θ·sin e_θ).

Обратная связь (`--localization`):
* `truth` — истинная поза из движка (идеальная локализация);
* `odom` — одометрия колёс по квантованным энкодерам (наименьшие квадраты по всем колёсам; у бортового поворота —
  `odom_yaw_scale`, как `wheel_separation_multiplier` в ROS diff_drive_controller);
* `odom_imu` — путь по колёсам, курс по гироскопу (нуль гироскопа усредняется на стоянке перед стартом).

После конца траектории замкнутый регулятор держит конечную точку, разомкнутый останавливается.

## 5. IMU и одометрия

IMU стоит в центре масс каждого робота: гироскоп (рад/с) и акселерометр (удельная сила, м/с²) в осях корпуса,
100 Гц. Каждое показание — среднее за период выборки плюс белый шум, постоянное смещение (случайное для `--seed`) и
блуждание смещения.

| пресет | гироскоп: шум / смещение / блуждание | акселерометр: шум / смещение / блуждание | класс |
|---|---|---|---|
| `none` | 0 | 0 | идеальный |
| `low` | 3·10⁻⁴ / 10⁻³ / 2·10⁻⁶ | 0.005 / 0.02 / 2·10⁻⁵ | промышленный MEMS (ADIS16470) |
| `default` | 0.002 / 0.005 / 2·10⁻⁵ | 0.03 / 0.1 / 2·10⁻⁴ | бытовой MEMS (MPU-6050, BMI088) |
| `high` | 0.01 / 0.02 / 10⁻⁴ | 0.2 / 0.3 / 10⁻³ | дешёвый + вибрация |

Шум — на одно показание, блуждание — на √с. Отдельные значения: `--set imu.gyro_sigma=...`.

В каждом прогоне пишутся три одометрии: идеальная (точные скорости шарниров), по энкодерам (квантованные счётчики) и
энкодеры + гироскоп. Штатный OdometryPublisher Gazebo (`--gz-sensors`) отдаёт истинную позу модели, а не одометрию колёс.

## 6. Воспроизведение записанных команд

```bash
bash scripts/drive.sh --robot husky --map my_map --replay cmd.csv --replay-mode wheels   # t,g0,g1,...: скорости колёс групп моторов, рад/с
bash scripts/drive.sh --robot youbot --surface gray --replay cmd.csv --replay-mode twist   # t,vx,vy,wz: скорость корпуса
#   --truth truth.csv   записанный путь t,x,y,yaw от старта — опора в логах и метриках
#   --v0 vx,vy,wz       запись начинается на ходу (эмулятор)
```
Так симуляцию сравнивают с записью своего робота: те же команды, та же поверхность, затем сравнение логов.

## 7. «Звезда» Robotino (`scripts/robotino.sh`)

```bash
bash scripts/robotino.sh --list                                            # библиотека поверхностей с параметрами
bash scripts/robotino.sh --engine emulate --surfaces real                  # 4 откалиброванных покрытия, все скорости
bash scripts/robotino.sh --engine harmonic --surfaces synthetic --jobs 4   # синтетические покрытия, 4 мира параллельно
bash scripts/robotino.sh --engine harmonic --surfaces carpet --speeds 0.2 --gui --rtf 5
bash scripts/robotino.sh --engine emulate --surfaces gray --quick          # 12 направлений по 6 с, проверка цепочки
bash scripts/robotino.sh --engine emulate --surfaces carpet --sweep carpet:mu=0.6,0.8,1.0
bash scripts/robotino.sh --engine emulate --surface-file examples/my_surfaces.json --surfaces user
```

| ключ | по умолчанию | смысл |
|---|---|---|
| `--engine` | harmonic | `harmonic`, `emulate`, `surrogate` (плоская модель, для переборов) |
| `--surfaces` | real | имена и/или группы `real`, `synthetic`, `hard`, `extreme`, `user`, `all` |
| `--speeds` | по поверхности | например `0.1,0.3` м/с |
| `--dirs` | 0:355:5 | направления лучей: `начало:конец:шаг` в градусах или список |
| `--t-run`, `--t-pause` | 18/10/6 с, 1.5 с | длительность луча (для 0.1/0.2/0.3 м/с), пауза между лучами |
| `--noise` | both | датасеты `clean`, `noisy` или `both` |
| `--map`, `--return` | – | звезда на карте рельефа; возврат в центр после каждого луча |
| `--set`, `--sweep`, `--surface-file` | – | поменять параметры, перебрать один, добавить поверхности |
| `--strict-format`, `--no-ext`, `--no-full`, `--no-figures` | | что писать ([DATASETS](DATASETS.md)) |
| `--gui`, `--rtf`, `--jobs`, `--dt`, `--seed`, `--out` | | как в `drive.sh`; папка по умолчанию `datasets/<дата>_<движок>` |

Объединение и дополнение папок с датасетами:
```bash
python3 tools/robotino_merge.py datasets/<a> datasets/<b> --out datasets/<объединённая>   # при совпадении побеждает последняя
bash scripts/robotino_missing.sh datasets/<папка> --engine emulate                       # досчитать недостающие пары (поверхность, скорость)
```

## 8. Проходимость (`tools/traverse.py`)

Каждый робот × каждая поверхность × уклон, задача у всех одна: прямая с регулятором пути по истинной позе.
```bash
python3 tools/traverse.py                                          # все роботы, 12 поверхностей, уклоны 0/10/20/30°
python3 tools/traverse.py --robots burger,waffle --angles 0,5,10,15,20,25 --jobs 4
python3 tools/traverse.py --engine harmonic --robots burger --surfaces gray,sand_lete
```
Результат (`runs/traverse_<дата>`): `runs.csv` (прогресс, проскальзывание, ток / ток стопа, осадка, энергия на метр,
вердикт), `matrix_flat.png/.csv`, `max_slope.png/.csv`, `REPORT.md`. Вердикты: ok (прогресс ≥ 0.95), slow (≥ 0.5),
stuck.

## 9. Движки, скорость и воспроизводимость
* `--engine emulate` — то же ядро, что в Gazebo, с жёстким шасси; нужен только `scripts/build.sh core`.
* Результат детерминирован при заданных `--seed` (шум IMU) и `field_seed` (неоднородность поверхности).
* С `--jobs N` миры идут параллельно; у каждого прогона Gazebo своя партиция (`GZ_PARTITION`), топики не смешиваются
  (как посмотреть топики прогона — [ROS2](ROS2.md)).
* Прогон останавливается, если лог не растёт `--stall` секунд; статусы — в [OUTPUTS](OUTPUTS.md#5-статус-прогона).
